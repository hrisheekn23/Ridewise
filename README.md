# RideWise Assist

A Streamlit chat application for the NeoStats RideWise Assist hackathon. It uses the supplied SQLite database, the five supplied policy PDFs, and only the LLM endpoint provided by NeoStats.

## 1. Project layout

```text
ridewise-assist/
├── app.py
├── db.py
├── llm.py
├── policy.py
├── requirements.txt
├── .env.example
├── .gitignore
├── README.md
├── DECISIONS.md
├── ridewise.db
└── policies/
    ├── Rental Agreement & Terms.pdf
    ├── Cancellation & Refund Policy (v1).pdf
    ├── Cancellation & Refund Policy (v2).pdf
    ├── Late Return & Damage Penalty Schedule.pdf
    └── EV User Guide & FAQ.pdf
```

Keep the supplied database and policy documents unchanged.

## 2. Setup

Python 3.10 or newer is recommended.

Windows PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Open `.env` and enter the exact base URL, API key, and model name provided by NeoStats. Do not use another provider's credentials. Never commit `.env`.

Place `ridewise.db` beside `app.py` and the five policy PDFs in `policies/`. If your paths differ, update `RIDEWISE_DB_PATH` and `POLICY_DIR` in `.env`.

## 3. Run

```powershell
streamlit run app.py
```

Streamlit prints a local URL, normally `http://localhost:8501`.

## 4. How it works

1. The user selects Customer or Support agent.
2. The app asks the provided LLM to generate a read-only SQL query when operational data is needed.
3. The query runner rejects non-SELECT statements and opens SQLite in read-only mode.
4. Policy PDFs are extracted and split into chunks. A simple keyword retriever selects relevant passages.
5. The supplied LLM answers using the database results and policy excerpts.
6. The Evidence used expander displays the query and policy excerpts for checking.

## 5. Important limitations

- The NeoStats endpoint is assumed to be OpenAI-compatible. If the organisers provide a different API format, adapt `llm.py` to their official instructions.
- This is a hackathon starter, not production authentication. Customer-mode SQL checks are deliberately conservative but are not a substitute for a formal SQL parser and robust row-level access controls. Test it carefully before submission.
- Keyword retrieval is a simple baseline, not semantic search.
- Conflicting cancellation policy versions should be handled explicitly; do not silently invent which version applies.
- SQL generated by an LLM can fail on unfamiliar wording or schema details. Inspect errors and improve prompts as needed.
